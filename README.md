# Codex Resets QQ 邮件监控

本项目每小时检查 Codex Resets 的公开状态接口，并在第三方已分类的**全局**重置公告、预测或预测更新出现时，向同一个 QQ 邮箱发送通知。它不是个人额度、个人用量或个人账户状态的查询工具；公告和预测可能变化，也不构成服务承诺。

## 运行方式

GitHub Actions 的生产工作流在每小时第 00 分钟运行：`0 * * * *`。UTC 与北京时间的整点分钟相同，例如北京时间 14:00 对应 UTC 06:00。GitHub 的计划任务可能发生排队或延迟，因此实际检查时间不保证精确落在整点。

首次成功运行会发出“监控已启用”的激活邮件，并创建公开的 `state.json`，用于避免重复通知。后续邮件含义如下：

- **预测**：发现新的全局重置预警。
- **预测已更新**：预警的概率、时间窗口或公告内容发生变化。
- **确认**：发现新的已确认全局重置公告。

## 公开仓库设置

1. 创建一个新的公开 GitHub 仓库，推送本项目代码；不要把邮箱或 QQ 授权码写入文件、提交信息或命令历史。
2. 在 QQ 邮箱设置中启用 SMTP 服务，并按 QQ 的验证流程生成用于 SMTP 的授权码。授权码不是 QQ 登录密码。
3. 在仓库的 **Settings → Secrets and variables → Actions** 中新增两个 Actions secrets：`QQ_EMAIL` 和 `QQ_SMTP_AUTH_CODE`。只在网页表单中填写实际值，不要在本仓库或聊天中粘贴它们。
4. 在仓库 **Settings → Actions → General → Workflow permissions** 启用读写工作流权限。该权限仅供生产工作流提交 `state.json`，不会在拉取请求测试工作流中使用。
5. 打开 **Actions**，选择 **Monitor Codex Resets**，点击 **Run workflow** 手动运行一次。配置正确时，你会收到激活邮件；随后可能出现一笔由 GitHub Actions 创建的 `state.json` 提交。

生产工作流仅支持定时和手动运行，避免在拉取请求上下文中暴露密钥。测试工作流不读取 Actions secrets。`state.json` 只保存公开 API 派生的通知标记和时间戳，不保存邮箱、授权码或其他凭据。

## 计划任务停用排查

公开仓库如果连续 60 天没有仓库活动，GitHub 可能自动禁用计划工作流。若整点邮件和 `state.json` 更新停止，请打开仓库的 **Actions** 页面，选择 **Monitor Codex Resets**，检查工作流是否显示为已禁用以及近期是否仍有定时运行记录。若已禁用，点击 **Enable workflow** 重新启用，再点击 **Run workflow** 手动触发一次；确认该次运行成功、激活或状态邮件符合预期，并继续观察后续整点运行。

## 安全维护

若怀疑授权码泄露，请立即在 QQ 邮箱设置中撤销或更换该授权码，再更新对应的 Actions secret。要停止服务，可在 Actions 页面禁用该工作流，或删除两个 Actions secrets。

绝不要在 issue、提交、日志、截图或寻求支持的消息中放入真实 QQ 邮箱、QQ SMTP 授权码或其他凭据。公开仓库中的示例只使用上述符号化 secret 名称。
